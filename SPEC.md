# Folly Studio — build contract

The shared contract for everyone building `studio/`. Code may refine details, but the
**interfaces** below are what the pieces rely on; change them here first.

Folly Studio is a web app where people log in, describe a show idea, get it turned into
pattern code, see it on a browser model of the Gothic Folly, edit it, and export it toward
the real installation.

## Ground rules

- **Zero npm dependencies.** Node ≥ 22 built-ins only (`node:http`, `node:crypto`, `node:fs`,
  `node:test`). No CDN either: the browser side is vanilla JS + WebGL2, so it works offline on
  the playa. ES modules everywhere (`"type": "module"`).
- **Every LED comes from the canonical pixel CSV pipeline** (`td/python/make_pixel_csv.py`),
  never re-derived by hand.
- **Pattern code is untrusted.** It only ever runs inside the sandbox page (below), never in the
  app page and never in Node on the server (except in tests, on our own library patterns).
- Coordinates follow the repo: **x = depth** (front/playa −12 m → back +14 m), **y = height**
  (0 → 18.5 m), **z = left → right** (−9 → +8 m) facing the portal from the playa.
- 40 fps, 510 channels per universe, universes 1–80 (xLights networks), so a full frame is
  80 × 510 = **40,800 channels**. Absolute channel (0-based) of a pixel =
  `(universe − 1) × 510 + (channel − 1)`; R, G, B follow.

## cathedral.json

```jsonc
{
  "version": 1,
  "count": 4870,
  "channelsPerUniverse": 510,
  "universes": 80,                 // frame = universes × channelsPerUniverse channels
  "bounds": { "min": [x,y,z], "max": [x,y,z] },   // metres
  "zones":   ["main-arch", "mini-arch-left", ...],            // CSV zone names, CSV order
  "strands": [ { "zone": 0, "name": "Main arch 1", "start": 0, "count": 228 }, ... ],
  "pixels": {                      // parallel arrays, length = count, CSV order
    "zone": [int], "strand": [int], "universe": [int], "channel": [int /* 1-based */],
    "row": [int /* rose ring 1-7, else 0 */],
    "pos": [x0,y0,z0, x1,y1,z1, ...]   // metres, 3 decimals
  },
  "groups": [                      // xLights-style tree; membership = zone in zones OR strand in strands
    { "id": "cathedral", "name": "Cathedral", "parent": null, "zones": [/* all */] },
    { "id": "arches", "name": "Arches", "parent": "cathedral", "zones": [...] },
    { "id": "main-arch-1", "name": "Main arch 1", "parent": "main-arches", "strands": [0] },
    ...
  ],
  "views": { /* td/config/views.json "views", verbatim */ }
}
```

A strand is one chain from the pixel map (one arch, one quad face, one spire strand, one rose
petal, …). Groups must cover at least: Cathedral; Arches → Main arches (each arch), Mini arches
left/right (each arch), Quad arches (each of the 6); Spires (each of 4); Spirelets; Rose window
(each petal, plus rings 1–7 as groups with a `rows` field: `{ "rows": [3] , "zones": [rose…] }`
meaning zone ∈ zones AND row ∈ rows); Canopy; Wash.

## Pattern code (what people and the AI write)

A pattern is a plain script (not a module). It defines `pixel`, and optionally `params` and
`frame`. Everything in the stdlib is in scope as globals.

```js
// Rising embers: warm sparks drift up every surface.
const params = {
  speed: { value: 0.4, min: 0, max: 2 },
  color: { value: '#ff6a00', type: 'color' },
};

function frame(t, P) {}            // optional: once per frame, before pixel()

function pixel(p, t, P) {          // every LED, every frame
  const v = pulse(fract(p.ly * 3 - t * P.speed), 0.2);
  return scale(P.color, v);        // [r, g, b], each 0..1 (optional 4th = alpha)
}
```

`P` holds each param's current value (`color` params arrive as `[r,g,b]`). Param kinds:
number `{ value, min, max, step? }`, `{ value: bool, type: 'toggle' }`,
`{ value: '#rrggbb', type: 'color' }`.

### The pixel `p`

| field | meaning |
|---|---|
| `x y z` | 0..1 across the whole cathedral (depth, height, left→right) |
| `X Y Z` | metres |
| `lx ly lz` | 0..1 across the pixels this layer targets (so a pattern fills what it lands on) |
| `a r` | angle 0..1 (clockwise from 12 o'clock, seen from the playa) and radius 0..1, in the façade (z–y) plane round the centre of this layer's pixels |
| `u i n` | position 0..1 along its strand, index along it, strand length |
| `zone zi strand` | zone name, zone index, strand index |
| `row petal` | rose ring 1–7 and petal 0–15 (0 / −1 elsewhere) |
| `k seed` | global index; a stable random 0..1 per LED |

### Stdlib (globals inside pattern code)

`PI TAU sin cos tan asin acos atan atan2 abs min max floor ceil round sqrt pow exp log hypot sign`,
`clamp(v, lo=0, hi=1)`, `fract(x)`, `mix(a, b, t)` (numbers or colours), `step(edge, x)`,
`smoothstep(e0, e1, x)`, `wave(x)` = ½+½·sin(2πx), `tri(x)`, `saw(x)`, `pulse(x, width)`
(1 near 0 falling to 0 at ±width, wrapping), `hash(n)` and `rand(a, b?, c?)` (stable 0..1),
`noise(x, y?, z?, w?)` (smooth 0..1), `fbm(x, y, z, octaves=4)`, `hsv(h, s, v)`, `hsl(h, s, l)`,
`rgb(r, g, b)`, `hex('#rrggbb')`, `scale(c, k)`, `add(c1, c2)`, `gradient(t, [c0, c1, ...])`,
`cosPalette(t, a, b, c, d)` (Inigo Quilez), `beat(t, bpm)` (phase 0..1), `dist(x1,y1,z1,x2,y2,z2)`.
Colours are `[r, g, b]` arrays, 0..1.

## Looks (what gets saved)

A look is a stack of layers, composited bottom to top like xLights rows reversed (index 0 is the
bottom):

```jsonc
{ "title": "Coral reef", "summary": "…", "layers": [
  { "id": "l1", "title": "Sea", "code": "…pattern source…", "groups": ["cathedral"],
    "blend": "add" | "over" | "max" | "multiply", "level": 1, "params": { "speed": 0.4 } }
] }
```

`groups` is an array of group ids (union). `params` overrides the code's defaults. Blend:
`add` sums light (default), `over` replaces where the layer has alpha × level, `max` keeps the
brighter channel, `multiply` tints what is below.

## Sandbox protocol (runtime.js ⇄ sandbox.html)

The app embeds `<iframe sandbox="allow-scripts" src="/sandbox.html">`. The server serves
sandbox.html with `/*@CORE@*/` replaced by `public/js/pattern-core.js` and the header
`Content-Security-Policy: default-src 'none'; script-src 'unsafe-inline' 'unsafe-eval'; sandbox allow-scripts`
(opaque origin, no network, no cookies). Messages use `postMessage(msg, '*')`; the app checks
`event.source === iframe.contentWindow`.

| app → sandbox | sandbox → app |
|---|---|
| `{ type: 'init', cathedral }` | `{ type: 'ready' }` (also sent once on load, before init) |
| `{ type: 'look', layers }` | `{ type: 'compiled', layers: [{ id, ok, error?, params: schema }] }` |
| `{ type: 'frame', seq, t }` | `{ type: 'frame', seq, rgb: Float32Array(count×3), errors: [{ id, error }], ms }` (rgb transferred) |
| `{ type: 'render', seq, start, frames, fps, gamma, brightness }` | `{ type: 'progress', seq, done }` … then `{ type: 'rendered', seq, channels: Uint8Array(frames × 40800) }` |

A layer that throws or returns NaN goes black for that frame and is reported in `errors`.
The app tears the iframe down and reloads it if a `frame` reply takes over 2 s.

`pattern-core.js` exports (used by sandbox.html and the Node tests):
`STDLIB`, `compilePattern(code) → { pixel, frame, params }` (throws on syntax error / no `pixel`),
`prepareScene(cathedral) → scene`, `prepareLayer(scene, layer, compiled) → prepared`,
`renderFrame(scene, preparedLayers, t, out?) → { rgb, errors }`,
`toChannels(scene, rgb, out?, { gamma = 1, brightness = 1 }) → Uint8Array(40800)`.

`fseq.js` exports `writeFseq({ channelCount, frames, stepMs = 25, data: Uint8Array }) → Uint8Array`
(FSEQ v2.0, uncompressed, no sparse ranges).

## HTTP API (JSON; cookie session)

Mutating requests must be `Content-Type: application/json` and, when an `Origin` header is
present, same-origin. Errors are `{ error: "message" }` with a 4xx/5xx status.

```
POST   /api/signup   { username, password }   → { user }            (sets cookie)
POST   /api/login    { username, password }   → { user }
POST   /api/logout                            → { ok: true }
GET    /api/me                                → { user } | 401
GET    /api/ideas                             → { ideas: [idea] }    mine, newest first
POST   /api/ideas    { text }                 → { idea }             queued for generation
GET    /api/ideas/:id                         → { idea }             mine only
GET    /api/looks?scope=mine|gallery          → { looks: [look] }
POST   /api/looks    { title, summary?, layers, ideaId? } → { look }
GET    /api/looks/:id                         → { look }             mine, or shared
PUT    /api/looks/:id { title?, summary?, layers?, shared? } → { look }   owner only; keeps versions
DELETE /api/looks/:id                         → { ok: true }         owner only
GET    /api/library                           → { patterns: [{ name, title, summary, code }] }
```

`user = { id, username, role: 'member' | 'curator' }` (curators listed in `STUDIO_CURATORS`).
`idea = { id, owner, text, status: 'queued'|'generating'|'ready'|'failed', generator, lookId?, error?, createdAt, updatedAt }`.
`look = { id, owner, ownerName, title, summary, layers, shared, ideaId?, reviewed, createdAt, updatedAt }`.

## Generators (idea → look)

`src/generate/index.js` runs a small in-process queue. An adapter is
`async generate({ text, user, library, groups }) → { title, summary, layers }` and is chosen by
`STUDIO_GENERATOR` (`sketch` default, `claude`, `fleet`). The result is validated (≤ 4 layers,
known group ids, code ≤ 20 kB containing `function pixel`) before a look is saved and the idea
set `ready`.

- `sketch`: offline, keyword → library pattern(s) + params. Always available.
- `claude`: one Messages API call with the pattern guide + library examples as the system prompt.
- `fleet`: hands the idea to a boxed Fleet worker as an untrusted brief (experimental).
